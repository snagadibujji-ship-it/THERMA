# 02 — Evidence Classes and Status Discipline

## Why this file exists
The THERMA record contains three different kinds of technical statements: external evidence, mathematical calculations, and project hypotheses. A fourth class contains facts that require hardware measurement. Mixing these categories is one of the easiest ways to make a deep-tech dossier look stronger than its evidence warrants.

## Class A — Established external science
Class A includes published thermoacoustic principles, experimentally demonstrated device classes, established equations, relevant engineering standards, and identified prior art. A Class A statement should identify the relevant source.

## Class B — First-principles calculation
Class B includes calculations such as water sensible heating, energy balances, Carnot ceilings, flow energy, and other results that follow from stated equations and assumptions. A calculation is valid only within its stated inputs and does not prove that a THERMA prototype will achieve the result.

## Class C — THERMA screening model
Class C is used for project-specific simulations and architecture targets. Examples include a historical COP target, a proposed module operating range, or a projected cold-room performance estimate. These outputs can guide design, but they are not measurements.

## Class D — Hardware-only evidence
Class D requires an instrumented physical prototype. Examples include real cooling capacity, actual acoustic amplitude, pressure leakage, fatigue life, regenerator degradation, thermal shock response, endurance, and certification.

## Reporting rule
Every major numerical result should state:
- source temperature;
- sink temperature;
- target temperature;
- thermal input;
- acoustic/electrical work where applicable;
- output heat or cooling capacity;
- COP definition;
- duration;
- model fidelity;
- evidence class.

## What the current dossier supports
The supplied v1 dossier states that THERMA-specific performance, geometry, materials life, pressure integrity, certification and commercial readiness are not experimentally proven. The repository therefore treats the project as a research/pre-prototype program, not a certified product.

## What this prevents
This discipline prevents a screening value from silently becoming a specification, prevents a literature result from being presented as a THERMA measurement, and makes future prototype data easy to compare against the pre-test model.
